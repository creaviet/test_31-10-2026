Review Product Requirement Document (PRD). Check the user journeys, scope, and out-of-scope features.

# Beginner Rule
Do not use the PRD to describe database tables, frameworks, endpoints, or file structure. Save those decisions for the technical specification. The PRD should explain the product clearly before the technical solution begins.

# Goal and metric format
Product goal:

[This product helps] [target user] [achieve outcome] [under important constraint or content].

Success metric:
- Metric 1: [measurable user or business result]
- Metric 2: [quality or adoption signal]
- Metric 3: [failure or risk signal to monitor]
