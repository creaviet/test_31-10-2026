Review Technical specification. Check whether it is ready for the next stage. Identify architecture risks, missing information, vague statement, risky assumption and security gaps. Also check the APIs.

Identify the exact corrections needed. Do not move to implementation.

# Checklist
Question the tech spec answers | What you should define
--- | ---
What is the system? | The purpose, users, boundaries, and main capabilities
How is it organized? | The architecture style, layers, components, and data flow
What does the user interact with? | Screens, forms, states, and validation rules
What topic runs behind the scenes? | Services, workflows, permissions, background jobs, and integrations
How is data stored? | Entities, relationships, constraints, indexes, and retention rules
How do parts communicate? | API endpoints, request formats, response formats, and status codes
How is quality protected? | Security, performance, reliablility, and error-handling requirements
